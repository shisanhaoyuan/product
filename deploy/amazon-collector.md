# Amazon 自有插件采集

“数据接入 → 亚马逊 · 集物自有采集”接受 ASIN、所选站点的 Amazon 商品网址（美国 amazon.com／加拿大 amazon.ca）和 Excel 链接表。系统按持久化任务编排插件、必要时调用服务器 Wraith，核对每个 ASIN 后通过统一 ImportBundle 入库。该编排不需要新增 AI Key，不执行网页提供的脚本指令，也不会提交沃尔玛。

## 员工使用

1. 更新服务器后，从数据接入下载“集物采集插件”ZIP，解压到固定文件夹。
2. Chrome/Edge 打开扩展管理，开启开发者模式，加载已解压扩展。已有旧版插件的员工需要替换原扩展文件、重新加载，再刷新商品库及已打开的 Amazon 页面。以页面显示版本为准，所有采集入口共用同一个插件和安装／更新说明。
3. 打开公司商品库网站，点击插件“连接当前商品库网站”，授权这个网站并刷新页面。
4. 先选择采集站点（美国 US／加拿大 Canada），再输入 ASIN／网址，或选择／拖入 XLSX、CSV、TSV。表头支持 `ASIN`、`商品链接`、`网址`、`URL` 等；无表头的单列 ASIN／网址也可识别。链接应存为文本，公式不执行，旧 XLS 先另存 XLSX。
5. 核对识别数量、无效行和是否采集子变体，点击“开始采集并入库”。每份表最大 150 MB，最多扫描 10000 行，每批最多 100 个输入，展开变体后最多 500 个 ASIN。
6. 保持数据接入页面与浏览器开启。可暂停、继续，或结束并保存已经采集的商品。失败信息逐 ASIN 显示；失败项可在新任务重新采集。当前运行任务及未结束的历史任务提供“取消采集”，取消后不入库本批结果、清除待入库资料并释放任务名额；已入库的历史商品保留。已取消任务不能继续或结束入库。已经开始的 Wraith 请求可能继续运行到结束，但结果会被丢弃，不再入库。

Chrome 与 Edge 的各自普通浏览器档案保存各自的 Amazon 地区 Cookie。配送邮编缺失／失效时，插件才自动切到 Amazon 页，美国站设置 10001、加拿大站设置多伦多 M5V 3L9 后继续。加载中的空地址不会立即弹窗。后续新任务默认后台标签页，不继承上一次“打开网页处理”的前台状态。不使用无痕模式。

验证码页触发一次服务器 Wraith 备用任务，沿用现有最多 3 次尝试预算；失败后在系统提供“打开网页处理”，不自动反复抢焦点。员工浏览器 Cookie 不上传服务器。Wraith 美国站使用原服务器浏览器档案，加拿大站使用同目录名加 `-ca` 的独立档案和加拿大邮编，不能把员工已设置邮编等同于服务器已设置成功。

## 采集规则

- 子变体优先从包含当前 ASIN 的 `dimensionToAsinMap`、`asinVariationValues`、`dimensionValuesDisplayData` 等映射发现，再补充变体按钮、下拉选项。推荐商品映射不使用，不用颜色数乘尺寸数生成不存在的组合。
- 每个发现的子 ASIN 独立打开并核对页面 ASIN，独立采集价格、图片、标题、卖点、规格和选中的颜色／尺寸等属性。子页面可补发现更多组合；明确的父 ASIN 冲突拒绝合并。未证明完整的变体列表保留提示。
- 定位普通报价，展开 Sellers on Amazon，加载“更多报价”并滚动到稳定后才判断报价是否唯一。排除会员专享、非新品、置顶推荐、隐藏报价及不属于当前 ASIN 的报价。
- 支持旧版 buybox 的可见价格字段，分别保存当前售价与同报价原价。85.49 当前价／89.99 原价仍分别保留；倍率计算沿用现有原价规则。
- 多个普通报价、未加载完整或未公开的价格保留缺项，不能编造价格。“有货”不等于实际库存数量；只有明确缺货才记录 0，数量未知需在预上架核对。
- 图片兼容旧版脚本图库、主图当前地址和商品图片区的高清／动态地址；等待图片加载后再采集，只读取当前 ASIN，不借用推荐或其他变体图片。静态补采没有图库时转员工浏览器采集。图片走既有受控下载与缓存；失败时保留来源链接和警告，不声称外部图片永不过期。
- 同一批已确认的变体关系去重；再次输入库内已关联子 ASIN 会定位原采集商品组。美国来源 namespace 为 `amazon-browser-us`，加拿大为 `amazon-browser-ca`，不会合并／改写历史数字酋长模板。
- 商品及报价记录原子落库，完成请求幂等。已保存结果可重复查看，写请求不自动重放。较旧任务不得覆盖较新采集，人工编辑覆盖层保持。

## 服务器更新

沿用项目现有备份、拉取代码、安装 Python 依赖、`frontend/npm ci` 与构建、重启服务流程。前后端与 `browser-helper` 必须一起更新。服务器原 `CATALOG_AMAZON_BROWSER_PYTHON` 等 Wraith 配置继续使用，不需要在员工电脑安装 Python 或 Wraith。

大表格上传上限为 150 MB。部署模板已同步 `client_max_body_size 150m;`；已运行的宝塔／Nginx 站点也需要将原 21m 改为 150m，执行 `nginx -t` 后 `nginx -s reload`。仅 Git 更新不会修改已启用的代理配置。后端上传流写入临时文件，解析结束自动清理；CSV 按流读取，XLSX 保留解压体积、共享文本及行列保护。

启动会执行迁移 26、27，新增 `amazon_import_jobs`／`amazon_import_items`／`amazon_import_execution`；SQLite 与 PostgreSQL 均支持。数据库备份包含任务表，SQLite → PostgreSQL 迁移清单已包含它们。回退旧代码可保留新增表；不要覆盖线上商品库或图片目录。

每人最多一个活动浏览器采集，最多五个未结束任务；其他员工独立采集。服务器 Wraith 备用队列最多 20 个，全局一次处理一个，沿用现有进程／档案锁。后台任务要求原操作者仍有效且有编辑权限。断线、刷新、租约到期或重启后可继续任务。新版页面每 15 秒续期设备执行权，90 秒无心跳后允许继续未完成项；已采集结果保留。单商品租约仍为 15 分钟，由心跳续期；插件单次等待 10 分钟。第二台设备只能查看正在运行的任务，争抢执行权失败不会暂停第一台。旧页面没有设备心跳，沿用旧租约，更新后应刷新页面。

## 验证与参考

参考的是现有自有代码的提取规则，不是数字酋长专有插件：

- `table-selection-mvp/mvp/market_signals.py`：当前 ASIN 映射、真实子 ASIN 与完整性证据。
- `商品信息更新/update_products.py`、`extractor/offer_selection.py`：普通价、卖家报价展开和懒加载稳定检查。
- `digit-emperor-ai-listing-test/src/amazon_capture.py`：规格表、详情参数、当前选中属性。

本次测试使用隔离数据库、模拟 Amazon 页面和平台响应。`validation/amazon_collector_check.py` 用实际加载的扩展验证 Excel 拖入、后台子商品采集、分别存价、入库、移动布局和报价展开。`validation/amazon_regular_price_check.py` 验证插件与 Wraith 共用规则的普通价／原价区分。真实 Amazon 页面及真实 Wraith 验证成功率需部署后联调，不能由模拟测试保证。

## 美国／加拿大分库

插件 2.1.0 增加 amazon.ca 权限，升级后须重新加载扩展。商品库菜单分别提供“亚马逊商品库 US”和“亚马逊商品库 Canada”。同 ASIN 的价格、子变体、图片关联、采集记录及人工编辑按来源独立保存；不会自动复制美国商品到加拿大。加拿大价格按 CAD 展示，预上架只允许加拿大店铺，不自动换汇。旧数据及不含站点信息的历史任务继续按 US 解释，无需新增数据库迁移。表格链接必须与所选采集站点一致，纯 ASIN 按所选站点处理。

## 2026-11-27 采集与进度修复

必须同时更新服务器前后端及员工插件 **2.2.0**，重新加载扩展并刷新商品库和 Amazon 页面。旧插件不会自动获得报价等待及新版容器解析修复。

- 报价区等待实际数据与页面稳定，无价格时最多等待 30 秒，再保留部分资料；支持无外框尺寸但子元素可见的容器，以及新版 Apex 价格、按钮中的卖家文字。
- 商品缺价格、卖家、配送时间或运费仍可入库，任务显示“待补齐”及具体缺项，商品档案保留采集警告。ASIN 不匹配、验证拦截页仍不能当作有效商品资料。旧缺项需要重新采集补齐。
- 顶部进度条每 2 秒同步服务器状态，展示已处理、已采集、待补齐、失败和当前阶段。明细默认折叠；暂停保留进度，结束保存已采集商品，取消不入库置于更多操作。
- 执行权跨整个批次保留，避免设备在两个 SKU 之间抢占。迟到的旧执行结果拒绝写入；不同账号本机采集互相独立。Wraith 因共享服务器浏览器档案仍保持单通道，不能通过盲目增加线程解决页面缺项。
