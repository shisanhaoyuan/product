# Amazon 后台浏览器采集

普通请求取得同一 ASIN 的页面后，如果报价需要动态展开、缺少原价或缺少配送地区，可使用 Wraith 后台浏览器读取。校验 ASIN 和报价后，沿用现有的价格、图片和 AI 填充流程。遇到验证码、访问限制或身份不符时停止。

## 阿里云服务器启用

在 root 终端先运行原有 Git 更新脚本，再运行安装脚本：

```bash
cd /www/wwwroot/jiwu && bash deploy/update-git.sh && bash deploy/enable-amazon-browser.sh
```

安装脚本使用独立的 Python 环境和缓存；需能访问依赖及浏览器官方下载源。以 jiwu 用户完成空白页启动检查后，写入独立的 systemd 配置并重启服务。看到“Wraith 已启用，jiwu 健康检查通过”才表示部署成功。缺系统库时按安装错误处理，不替换系统 GLIBC。回退：移除 /etc/systemd/system/jiwu.service.d/70-jiwu-amazon-browser.conf，再执行 systemctl daemon-reload 和 systemctl restart jiwu（如原 /etc/jiwu.env 曾单独配置浏览器，也需取消该配置）。

## 数据与确认边界

使用临时独立浏览器会话，不借用用户浏览器配置、登录态或凭据，不自动购买代理或调用外部验证码付费服务。仅把目标商品和报价的 HTML 片段传回应用，沿用同 SKU 解析与身份校验。返回成功、HTTP 200 或 Cookie 存在都不等于报价已核验。

人工补价只保存到当前批次、当前店铺及当前子 SKU。服务端按来源原价乘本批次倍率、ROUND_HALF_UP 两位计算；记录人工原价、倍率、最终售价及操作者。缺少建议零售价时提供两倍售价的建议值（可修改、非强制）。不会把人工数值写成自动抓取证据；售价或来源变化会使人工确认失效。库存、EAN、类目、店铺与沃尔玛字段校验继续生效。

## 图片采集

来源报价采集同时解析已核验当前 ASIN 的图片画廊，不采集推荐商品和其他变体。
AI 生成前会对当前 SKU 的主图、附图及来源图片进行下载校验，保存到既有图片存储
（服务器部署沿用 `CATALOG_IMAGE_STORAGE=filesystem` 和 `CATALOG_IMAGE_ROOT`）。
相同文件按内容去重，已缓存的同 SKU 图片可复用；每轮最多采集 32 张，两张并发，单张限 8 MB。
采集结果显示保存数量和失败原因，图片失败不会丢失已采集报价。旧图片链接仍可从原始快照追溯。

本地图片用于 AI 读取；正式提交时沿用 `/api/listing-media/` 的公开刊登图片链接。
`CATALOG_PUBLIC_ORIGIN` 必须是沃尔玛能访问的 HTTPS 站点，反向代理需要保留该路径。
保存成功不代表外部平台一定可访问，平台反馈主图缺失时仍需核对公开链接。
新增供应商 CDN 须明确配置可信 `CATALOG_LISTING_IMAGE_HOSTS`（逗号分隔域名），不能开放任意地址。
数字酋长导入图片的 `ps-cdn-s3.datacaciques.com` 和 `pg-cdn-a2.datacaciques.com` 已内置支持，无需额外服务器配置。
若数字酋长图片全部或部分下载失败，且本轮尚未采集当前 Amazon ASIN，生成阶段会尝试一次当前 ASIN 原图补采；不覆盖人工价格，不借用其他变体图片。
失败提示会显示被拒绝的域名或图片服务器 HTTP 状态；不包含链接查询参数。升级后重新生成即可重试旧的失败记录。
浏览器验证助手的来源模式也会附带当前画廊；已安装旧助手时需重新下载并加载新版本。

图片部分失败时也会尝试一次补采，保留成功下载的图片。已确认失败的旧链接从本次刊登主图／附图中移除，失败详情保留供核对；原始商品快照不变。AI 识图只读取本轮已保存的图片，不会再次请求这些失效链接。
