# 阿里云 + 宝塔：PostgreSQL 与服务器图片目录

当前部署方案：Vue 3 + FastAPI + PostgreSQL 16 + 本机独立图片目录。已确认目标为 Alibaba Cloud Linux 3、x86_64，Python 3.11、Node 22、Git 与 Nginx 已安装。服务器 PostgreSQL 安装情况及 HTTPS 尚需现场确认；本文不代表已经部署成功。

## 目录与权限

- 代码：`/www/wwwroot/jiwu`，root 所有，服务用户只读，通过 Git 更新。
- 数据库：PostgreSQL 的 `jiwu` 数据库，专用非超级用户 `jiwu`，仅本机访问。
- 图片：`/www/server/jiwu-data/images`，jiwu 所有，目录 700、文件 600；不放在 Git 或 Nginx 静态目录。
- 配置：`/etc/jiwu.env`，jiwu 所有、600，包含数据库凭据，不提交 Git。
- 备份：`/www/server/jiwu-backups`，700；另行复制到独立机器。
- 应用仅监听 `127.0.0.1:8765`，公网通过 Nginx HTTPS 访问。

图片由受登录保护的 API 提供。新上传图片去重后保存到磁盘，数据库只存摘要、路径和属性。删除商品图片只解除引用，保留文件用于历史记录；目前不自动清理未引用文件。已有 Amazon/ERP 远程图片链接仍保留原 URL，本次不会批量下载外链图片。

## 1. 准备 PostgreSQL

先检查现有服务，避免覆盖宝塔或其他应用的数据库。在服务器运行：

```bash
command -v psql pg_dump pg_restore
ss -lntp | grep -E ':(5432|8765)\b' || true
systemctl list-unit-files | grep -i postgres || true
dnf list --available '*postgresql*server*'
```

确认当前仓库能提供受支持的 PostgreSQL 16 后再安装；不能把发行版未知版本的包名直接套用。若已经有 PostgreSQL，使用该实例新建独立数据库，不重复初始化其数据目录。`pg_dump` 和 `pg_restore` 使用与数据库同版本的客户端；版本过旧会拒绝备份。

由数据库管理员在 `psql` 中执行以下语句（仅新建实例；已有同名角色/库时先核对用途）：

```sql
CREATE ROLE jiwu LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
\password jiwu
CREATE DATABASE jiwu OWNER jiwu ENCODING 'UTF8' TEMPLATE template0;
```

`\password` 交互输入密码，避免在命令历史、聊天中明文传递。应用角色需要在自己的数据库内建表及迁移，不授予超级用户权限。实例仅监听本机；按实际配置文件位置，在 `pg_hba.conf` 中为 `127.0.0.1/32` 的 jiwu 数据库/jiwu 用户允许 `scram-sha-256`，然后重载配置。不要覆盖现有其他规则或向公网开放 5432。

## 2. 通过 Git 安装代码

首次克隆和前端构建按 [Git 部署](Git部署.md) 执行。服务器没有该目录时才能克隆，已有目录先核对，不能强制覆盖。随后准备服务用户与目录：

```bash
id jiwu >/dev/null 2>&1 || useradd --system --home-dir /www/server/jiwu-data --shell /usr/sbin/nologin jiwu
install -d -m 700 -o jiwu -g jiwu /www/server/jiwu-data /www/server/jiwu-data/images /www/server/jiwu-backups
chown -R root:jiwu /www/wwwroot/jiwu
chmod -R g+rX /www/wwwroot/jiwu
```

只有首次配置且 `/etc/jiwu.env` 不存在时复制：

```bash
test ! -e /etc/jiwu.env && install -m 600 -o jiwu -g jiwu /www/wwwroot/jiwu/deploy/jiwu.env.example /etc/jiwu.env
```

在服务器编辑配置，替换 `CATALOG_DATABASE_URL` 中的密码；URL 中特殊字符必须百分号编码。不要发送配置内容到聊天。保留 `CATALOG_IMAGE_STORAGE=filesystem`、`CATALOG_IMAGE_ROOT=/www/server/jiwu-data/images`。不需要 OSS Bucket 或 AccessKey。公网地址为 `https://8.153.77.160`，更换 IP 时同时更改配置和证书。

```bash
cd /www/wwwroot/jiwu
runuser -u jiwu -- .venv/bin/python -m catalog --env-file /etc/jiwu.env storage-check
```

该命令建表并向图片目录写入一个小型探针文件，回读校验摘要。检查不通过时不要启动正式服务。

## 3. 首次迁移现有商品库

在原电脑先使用 SQLite 在线备份，不直接复制正在写入的 `.db`：

```bash
python -m catalog --db data/catalog.db backup /私有目录/catalog-migration.db
```

将此备份上传到服务器 `/www/server/jiwu-data/catalog-migration.db`（禁止放网站根目录），属主 jiwu、权限 600。迁移期间停用目标应用和全部外部写入程序。目标必须为空，不要先创建管理员或自定义店铺。若源使用独立图片目录，也必须先复制完整图片目录到目标配置位置；旧版默认 SQLite 图片二进制由迁移命令自动拆出。

```bash
systemctl stop jiwu 2>/dev/null || true
cd /www/wwwroot/jiwu
chown jiwu:jiwu /www/server/jiwu-data/catalog-migration.db
chmod 600 /www/server/jiwu-data/catalog-migration.db
runuser -u jiwu -- .venv/bin/python -m catalog --env-file /etc/jiwu.env migrate-sqlite /www/server/jiwu-data/catalog-migration.db
```

迁移保留 ID、来源、主子文案、价格、库存、黑名单、店铺、预上架批次、编辑与审计记录、账号与会话。源文件只读，目标逐行核对；图片逐个验证 SHA-256。失败回滚数据库，不覆盖源文件，可能留下可安全复用的未引用图片。重复同一备份返回已有迁移报告，不重复导入；目标已有其他数据会拒绝覆盖。此命令不是不同图片后端之间的搬迁工具。

迁移后核对报告与原库统计、主子 SKU、价格库存及图片；不重新乘倍率。不要在服务器投入使用后再次拿本机库覆盖。没有原账号时，迁移完成后交互创建管理员：

```bash
runuser -u jiwu -- .venv/bin/python -m catalog --env-file /etc/jiwu.env create-admin admin
```

密码至少 12 位，无默认密码。团队权限是全库级 admin/editor/viewer，不按店铺隔离。

## 4. 安装服务和 HTTPS

```bash
install -m 644 /www/wwwroot/jiwu/deploy/jiwu.service /etc/systemd/system/jiwu.service
systemctl daemon-reload
systemctl enable --now jiwu
systemctl status jiwu --no-pager
curl --fail -H 'Host: 8.153.77.160' http://127.0.0.1:8765/api/health
```

健康检查应包含 `database: postgresql`、`images: filesystem`。服务定义限制写入目录为 `/www/server/jiwu-data`。不要同时在宝塔另起一个占用 8765 的 Python 服务。

宝塔创建 IP 对应的独立站点，root 使用空目录 `/www/wwwroot/jiwu-public`，不能指向项目或数据目录。HTTPS server 内使用 `nginx-location.conf`，去除冲突的静态缓存和 `location /`。保留其他站点；先检查 `nginx -t` 再重载。阿里云安全组与系统防火墙只开放网站 80/443，不开放 8765/5432。

无域名时采用包含该公网 IP 的有效 HTTPS 证书。IP 证书申请、自动续期要求见 [Git 部署](Git部署.md)。保持登录与 Secure Cookie，不通过关闭权限来绕过 HTTPS。服务器证书申请和续期必须实际验收。

## 5. 验收、更新与备份

登录后核对模板数、子变体数、各店铺数，逐项抽查价格、库存、EAN、五点、描述、图片及历史来源。上传一张测试图片，保存后重新打开，再重启服务确认图片可读。检查未登录无法访问商品和图片、只读账号不能修改、禁用账号后会话失效。

日常更新：

```bash
bash /www/wwwroot/jiwu/deploy/update-git.sh
```

旧 SQLite 部署必须先按本说明完成迁移及配置；更新脚本不自动切库。脚本停服后备份数据库和图片，再快进更新 Git、安装依赖、构建、启动并检查健康状态。失败保留备份和日志，不自动回退数据库。

宝塔计划任务每日以 root 执行：

```bash
bash /www/wwwroot/jiwu/deploy/backup.sh
```

备份时短暂停服，保存 `catalog.dump`、`images.tar.gz`、`SHA256SUMS`、Git 提交号，成功后写 `COMPLETE`。原本运行的服务会恢复启动；原本已停止的服务保持停止。只保留带 `COMPLETE` 且摘要校验通过的备份作为有效恢复点。备份目录、配置和数据库密码须独立安全备份；脚本不会自动复制环境文件，也不删除旧备份。同机备份不能抵御磁盘损坏，需复制到另一台机器并定期演练。

## 6. 恢复演练

在独立测试数据库和图片目录操作，不能覆盖运行中的生产库。先 `sha256sum -c SHA256SUMS`，创建新的空库（owner jiwu），用同版本 `pg_restore --exit-on-error --no-owner --no-acl --dbname=新的测试库 catalog.dump` 恢复，数据库密码通过受限 `.pgpass` 或交互输入。将图片归档解压到独立数据目录，设置 jiwu 所有、目录 700 文件 600。新配置同时指向该数据库和图片目录。

使用维护连接执行 `DELETE FROM sessions;` 使恢复的旧会话失效。启动独立测试实例，核对全库数量和图片、子 SKU、编辑历史、权限；通过后才制定正式切换。正式回滚必须停服，恢复匹配的代码、依赖、数据库与图片，不能仅回退 Git 后假设数据格式兼容。

重置账号密码：

```bash
cd /www/wwwroot/jiwu
runuser -u jiwu -- .venv/bin/python -m catalog --env-file /etc/jiwu.env reset-password admin
```
