# 阿里云 + 宝塔：集物团队版部署

准备状态：代码已支持团队登录与权限，本文使用 Linux + 宝塔 Nginx + systemd。服务器的发行版、域名和连接方式尚待确认；尚未连接或部署到阿里云。

## 部署前确定

- 阿里云控制台的 ECS 实例系统与版本（Ubuntu 22.04/24.04、Debian 12 等），CPU 架构及内存。当前规模建议 2 核 2 GB 起步；与宝塔其他站点共用时建议 4 GB。
- 域名或子域名，例如 `catalog.your-domain.com`，解析到服务器公网 IP。阿里云中国内地实例使用域名提供网站服务需满足备案要求；实际以阿里云及所在地要求为准。
- 宝塔安装 Nginx，系统有 Python 3.11/3.12、venv 和 systemd。Python 命令按实际安装路径调整，不能覆盖宝塔自身的 Python。
- SSH 可用；私钥放在自己的电脑，不要粘贴到聊天。没有 SSH 时可在宝塔终端执行命令。

本包已含构建好的 Vue 页面，服务器不用安装 Node。仅在修改前端后才需要重新构建。

## 文件与目录

- 程序：`/www/wwwroot/jiwu`，只存代码和构建产物。
- 数据：`/www/server/jiwu-data/catalog.db`，不能放到网站可直接下载的静态目录。
- 环境：`/etc/jiwu.env`。
- 备份：`/www/server/jiwu-backups`。
- 服务：`jiwu.service`，Python 仅监听 `127.0.0.1:8765`；公网只经 Nginx HTTPS 访问。

每个成员使用独立账号。管理员管理成员、导入和查看；编辑员导入和查看；只读成员查看及导出。当前权限是全库级别，所有成员能看到所有店铺；没有按店铺或部门隔离。

## 1. 上传代码与数据库备份

本机生成发布包（已有发布包可跳过）：

```sh
python deploy/package_release.py /path/to/jiwu-release.tar.gz
python -m catalog backup /path/to/catalog-migration.db
```

第二条命令使用 SQLite 在线备份，包含当前商品、全部快照及已经存在的账号/会话。只在首次迁移使用，不能反复覆盖服务器日常更新后的库。代码包不含数据库、密码、Cookie 或上传项目的日志。

在宝塔文件管理中上传发布包到非公开临时目录，解压到 `/www/wwwroot`，确认得到 `/www/wwwroot/jiwu`。数据库备份单独上传到 `/www/server/jiwu-data/catalog.db`。首次迁移后即删除上传临时副本。

若目录已经有正式数据，先备份并停止操作，不要直接覆盖。以下命令仅用于新部署：

```sh
useradd --system --home-dir /www/server/jiwu-data --shell /usr/sbin/nologin jiwu
install -d -m 700 -o jiwu -g jiwu /www/server/jiwu-data
install -d -m 700 -o jiwu -g jiwu /www/server/jiwu-backups
chown jiwu:jiwu /www/server/jiwu-data/catalog.db
chmod 600 /www/server/jiwu-data/catalog.db
chown -R root:jiwu /www/wwwroot/jiwu
chmod -R g+rX /www/wwwroot/jiwu
```

数据库尚未导入也可先启动空库，但须明确页面会是空商品库。不要把空库误当成迁移成功。

## 2. 安装 Python 依赖

以下以已安装的 `python3.12` 为例；若用 3.11 或宝塔 Python，请替换命令路径：

```sh
cd /www/wwwroot/jiwu
python3.12 -m venv .venv
.venv/bin/python -m pip install -r deploy/requirements.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m pip check
```

数据库建在独立目录，代码升级不会覆盖商品数据。依赖版本通过 lock 固定；更改版本需重新验收。

## 3. 配置团队模式和管理员

```sh
install -m 600 deploy/jiwu.env.example /etc/jiwu.env
```

编辑 `/etc/jiwu.env`，将 `CATALOG_PUBLIC_ORIGIN` 改成实际 `https://你的域名`，不要加路径。保留 `CATALOG_AUTH_ENABLED=1` 和 `CATALOG_COOKIE_SECURE=1`。可选导入令牌不替代用户登录。

在宝塔终端交互创建首个管理员，密码输入不会回显：

```sh
cd /www/wwwroot/jiwu
runuser -u jiwu -- .venv/bin/python -m catalog --db /www/server/jiwu-data/catalog.db create-admin admin
```

密码至少 12 位，没有默认密码。程序保存带随机盐的 PBKDF2 密码哈希和服务端会话；会话 Cookie 为 HttpOnly、Secure、SameSite=Strict，有效期 12 小时。禁止将生产环境关闭登录作为排错方法。

## 4. 安装后台服务

```sh
install -m 644 /www/wwwroot/jiwu/deploy/jiwu.service /etc/systemd/system/jiwu.service
systemctl daemon-reload
systemctl enable --now jiwu
systemctl status jiwu --no-pager
journalctl -u jiwu -n 80 --no-pager
```

健康检查需要使用配置的域名作为 Host：

```sh
curl -H 'Host: 你的域名' http://127.0.0.1:8765/api/health
```

服务启动后有故障自动重启及开机启动。不用再在宝塔 Python 项目管理器重复创建第二个 8765 服务。

## 5. 宝塔网站和 HTTPS

1. 宝塔「网站 → 添加站点」添加实际域名，选择纯静态站点，关闭 PHP。不启用公开目录列表。
2. 网站 SSL 中申请并部署可信证书，开启强制 HTTPS。证书申请使用 HTTP 验证时保留宝塔的 ACME 验证配置。
3. 在该网站 HTTPS `server` 块中加入 `deploy/nginx-location.conf` 内容，删除或替换原来冲突的 `location /`；关闭该站点静态文件缓存/直接文件匹配规则，让 `/assets` 也转发到应用。
4. **网站 root 不能设成项目或数据库目录**。使用独立空站点目录，例如 `/www/wwwroot/jiwu-public`，所有应用请求由反向代理处理。
5. 宝塔检查 Nginx 配置并重载。域名需与环境文件完全一致；额外域名先重定向到主域名。
6. 阿里云安全组及服务器防火墙开放网站 80/443；8765 不对公网开放。保留现有 SSH/宝塔管理访问方式。

若要使用阿里云 CDN、WAF 或负载均衡，需另行核对真实客户端 IP、HTTPS 和 Cookie 转发；本文直接连接 Nginx。不要随意信任客户端传入的 X-Forwarded-For。

## 6. 迁移验收

- 浏览器访问 `https://你的域名`，未登录应进入登录页。
- 无 Cookie 访问 `/api/products`、`/api/export.json`、`/docs` 应返回 401；`/api/health` 可公开返回简单健康状态。
- 管理员登录后核对迁移清单的模板数、子变体数与各店铺数，抽查主子 SKU、价格、库存、EAN、五点、描述及来源记录。数据应与备份时一致，不重新乘倍率。
- 管理员「团队」添加编辑员及只读成员；新成员首次登录修改临时密码；确认只读账号不能导入或管理账号。
- 禁用成员后，其原设备访问受保护接口应失效。修改密码后所有旧会话应失效。
- 重启服务后数据仍存在、登录正常。确认外部不能直接下载 `.db`、环境文件或发布包。
- 最后生成一次服务器备份，并在独立测试环境打开备份确认可恢复。

本地通过测试不能替代服务器验收；真正的 HTTPS、证书续期、宝塔配置和阿里云安全组须在服务器验证。

## 7. 备份、升级与恢复

宝塔「计划任务 → Shell 脚本」每日运行（root）：

```sh
sh /www/wwwroot/jiwu/deploy/backup.sh
```

备份目录初次创建时按第 1 步授权给 jiwu；脚本不会自动删除历史文件。需另配阿里云 OSS 或其他独立位置备份并定期恢复演练；同机备份无法抵御磁盘丢失。备份包含账号和会话数据，限制访问。

升级前先备份数据库并保留旧代码/构建产物，再 `systemctl stop jiwu`，替换程序（保留 `.venv` 或重新安装锁定依赖），`systemctl start jiwu`，重新验收。不要覆盖 `/www/server/jiwu-data`。本次账号表迁移为幂等新增表，不更改历史商品表；后续结构变更须有版本迁移和回退方案。

密码遗忘由服务器管理者运行（撤销该用户全部会话，下次登录需改密）：

```sh
cd /www/wwwroot/jiwu
runuser -u jiwu -- .venv/bin/python -m catalog --db /www/server/jiwu-data/catalog.db reset-password admin
```

恢复备份时停止服务，使用经过核验的完整备份在受控环境替换数据库，处理旧 WAL/SHM 并重新设置文件属主。含旧账号会话的备份恢复后，应在停机状态下清空 `sessions` 表使历史会话失效，再启动服务。不要对运行中的数据库直接覆盖复制。
