# 每周来源巡查与沃尔玛自动更新

保留现有 `jiwu-giga-patrol.timer`：每周一 09:00（Asia/Shanghai），页面关闭不影响执行。`Persistent=true` 会在停机错过后补执行。更新代码后下一次定时任务使用新逻辑，无需另建 Codex 自动任务。

## 执行范围

检查当前已配置的大建云仓和赛盈 API 账号的已入库商品，两种来源独立记录巡查结果；其中一种失败不会阻止另一种执行。来源更新后，只操作本系统有已上架成功记录、当前有效提交归属和精确平台 SKU 映射的沃尔玛商品。未提交、审核中、失败、非这两种来源及其他 API 账号不自动修改。每个店铺独立核验 partner ID、授权版本、平台 SKU、原提交仓库。

- 涨价：来源单价和物流费构成单一、有效 USD 成本且成本上涨时，用 `(单价 + 物流费) × 该店铺原上架倍率`，四舍五入至两位小数。物流费包含打包费，不重复加打包费。只在计算目标高于沃尔玛回读现价时 PUT 更新，不降低售价，不对现售价重复乘倍率。初次巡查允许与原上架成本比较；确定未发送的失败在后续巡查以新鲜来源数据重算重试。
- 清零：仅本轮有效库存响应明确为 0 时，对原提交仓库写 0。不将缺失、超时、格式错误当成 0；不自动补库存，不按“小于 10”触发本功能。
- 价格和库存分别检查权限和记录结果。一项失败不阻止另一项、其他店铺或其他商品。
- 调用已有商品的 `/v3/price`、`/v3/inventory`，不提交 `MP_ITEM` 上架文件，不更换 SKU，不改标题、图片、品牌、描述及 MSRP。

## 权限与结果

服务器沿用现有店铺绑定、加密主密钥及 GIGA API 配置。自动改价需要 `price: full_access`，清零需要 `inventory: full_access`，并需要商品/库存读取能力。缺失权限时在巡查明细显示中文原因。

在“价格与库存巡查 → 查看明细”查看来源前后值，以及每店铺的 SKU、原倍率、计算公式、仓库、修改前值、目标值、回读值和时间。

- **已回读确认**：回读与目标一致。
- **无需修改**：当前售价已经不低于目标，或库存已经为 0。
- **未触发更新**：来源条件不符，不写沃尔玛。
- **结果待确认／等待上次结果**：已发 PUT 但超时、响应异常或回读尚未一致。后续每周巡查先回读，不能盲目重复发送。即使来源后来变化，也先核对未决请求。仍不一致时需在卖家中心核对，不要仅删除本地记录来解锁。
- **失败**：发送前身份、读取、权限等检查失败；符合条件时下周再试。

任务在 PUT 前持久保存意图，借用原提交结果查询锁避免两个本系统任务同时修改库存；在最终身份核验及单次 PUT 期间持有数据库写锁（可能短暂延缓本地编辑）。不保证与其他软件或卖家中心手工修改之间的跨系统原子性。

任务最长执行时间仍由原 systemd service 的 6 小时限制控制。中断留下的已发送请求先回读；来源锁为单次店铺操作预留 15 分钟，进程退出后由上下文释放，崩溃后到期释放。

## 部署与验证

使用现有 Git 更新脚本部署代码并重启 Web 服务。数据库启动时幂等新增巡查证据、店铺操作审计表，保留商品和历史记录；不导入或覆盖本地数据库。已有周任务无需重装；尚未安装时使用 `deploy/install-giga-patrol.sh`。

测试使用模拟 API 和隔离数据库，不能作为真实店铺授权或实际生效证明。首次服务器周任务后请检查页面明细与卖家中心回读结果。

接口依据：
- https://developer.walmart.com/us-marketplace/reference/updateprice
- https://developer.walmart.com/us-marketplace/reference/getanitem

## 赛盈巡查（2026-11-20）

沿用同一个每周一定时器，旧 service 的 `python -m catalog.giga_patrol` 更新代码后会依次检查已配置的大建云仓与赛盈，无需创建第二个定时器。仅配置赛盈也能安装此定时器。未安装时执行 `bash deploy/install-giga-patrol.sh`；已安装的无需重装。

- 从本地当前赛盈账号已入库记录取得 SKU，每批最多 30 个，只查询价格和库存，不发现新商品或重新导入描述图片。
- 固定当前已选站点、仓库、物流和 USD 报价，采购价采用 SellingPrice，缺失时回退 OriginalPrice；无需另加运费。已选报价消失、重复、币种错误不自动换仓；保留原值并记录错误。
- 分仓可用 Qty 不与明细或备货数量累加；新响应明确返回该仓 Qty=0 才允许沃尔玛清零。库存接口失败或 SKU 漏返，不能使用旧库存作为本轮成功证据。
- 价格和库存独立写入与记录，失败字段保留原值；手工编辑覆盖、标题、图片、描述和上架草稿保持原样。
- 沃尔玛更新仅针对已确认 published 的 SKU：采购价上涨，按采购价 × 原店铺上架倍率上调；明确为零则清零，非零不恢复库存、不自动降价。
- 新提交记录冻结来源账号、站点、仓库与物流。旧记录从批次预览读取原报价；无法找回或与本轮不一致时跳过自动更新，记录原因。原上架的仓库、平台 SKU、店铺身份核验及不确定请求先回读的机制共用。
- “赛盈商品库”及“数据接入 → 赛盈”均可进入赛盈专属“价格与库存巡查”，显示前后价格、库存、来源报价位置和各店铺更新明细。不会显示大建云仓或其他账号的巡查记录。

需要单独人工执行赛盈巡查时（会按上述规则同步已上架沃尔玛商品）：

```bash
cd /www/wwwroot/jiwu
runuser -u jiwu -- .venv/bin/python -m catalog.giga_patrol --env-file /etc/jiwu.env --source saleyee
```

默认不传 `--source` 表示巡查所有已配置来源；`--source giga` 只检查大建云仓。退出码非零表示某来源存在未完成或待处理项，详细情况以页面记录为准。
