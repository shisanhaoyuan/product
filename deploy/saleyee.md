# 赛盈 Saleyee 商品库接入

采用官方 Open API V2 AccessToken，通过 HTTPS 直接 POST 业务参数。

官方来源（2026-11-19 核对）：
- 开发者入口：https://www.saleyee.com/user/developerdetail/requestinformation.html
- V2 指南：https://openapi-doc.saleyee.com/9348743m0.md
- 商品详情：https://openapi-doc.saleyee.com/505139672e0.md
- 商品价格：https://openapi-doc.saleyee.com/505139673e0.md
- 库存：https://openapi-doc.saleyee.com/505139670e0.md

## 配置

在服务器已有 `/etc/jiwu.env` 添加两项，实际 AccessToken 只写入服务器私有文件：

```dotenv
CATALOG_SALEYEE_ACCOUNT=team-us
CATALOG_SALEYEE_ACCESS_TOKEN=替换为赛盈后台的V2令牌
```

`CATALOG_SALEYEE_ACCOUNT` 是自定义固定账号标识，用于隔离不同赛盈账号；同一账号换令牌时保持该标识不变。更换到另一赛盈账号时使用另一个标识，避免覆盖旧账号商品。不是用户名密码，不需要公开令牌。

保留配置原有的 jiwu 服务读取权限（通常 root:jiwu、640），不要覆盖整个环境文件。随后执行：

```bash
systemctl restart jiwu
systemctl is-active jiwu
```

打开“数据接入 → 赛盈”，刷新配置。按 SKU 同步每次最多 30 个；留空时分页读取 API 允许查询的商品。不能保证此集合等于收藏夹，实际范围由赛盈账号权限决定。操作员可停止后续页，已完成页保留。再次同步按账号标识＋SKU 更新，无需清空数据库。

## 页面与计价

“商品库”菜单新增“赛盈商品库”，与 Amazon、大建云仓分开。商品档案展示图片、文案、参数、包装字段、全部仓库报价和分仓库存；原始 API JSON 折叠保留。

- 报价有站点、仓库、物流、收货国家、币种。只自动采用唯一的美国收货国家 US、USD 报价；多报价时在商品档案选择。
- 用户确认 API 不提供运费。运费单独填写在商品档案，确认为免费配送才填 0。没有运费时可入库、建待复核草稿，不能正式提交。
- 计价：`（商品价＋对应报价的运费）×预上架倍率`；商品价优先采用正数 OriginalPrice，否则使用 SellingPrice，合计保留两位小数。例如 67＋2.33，倍率 1.4 → 97.06。
- 更换报价会清空旧运费；重复同步同一报价保留已填写运费。商品、报价、库存响应严格按同一 SKU 对齐；库存必须同站点、同仓库，不能叠加分仓明细、备货数量。
- 库存 ≥10 写 10，库存 <10 写 0；库存未知单独提示，不按 0 处理。“无库存”筛选仅包含已匹配仓库可用库存明确为 0 的商品。
- 普通商品和包装长宽高重没有明确单位时原样展示，不猜测单位或写入沃尔玛重量。组合配件 MapGroupList 保留，不能自动当子变体。
- 未上架、无商品权限、禁售沃尔玛、分销权限不明确、侵权/侵权待审核等信息阻止正式提交。

从列表或详情创建预上架，沿用店铺品牌、平台 SKU、编码池、模板复用、AI 资料准备、沃尔玛实际类目必填校验、提交及“审核进度”。EAN/UPC 仍使用真实编码池或已批准的豁免，赛盈商品 SKU 不充当 EAN。商品详情缺失的供应商名称不使用品牌伪装。

API 只读白名单为商品详情、价格、库存、仓库；不创建或支付赛盈订单。请求按顺序限流，遇 429/临时服务异常仅有限重试；单页缺失/重复/错 SKU 或异常数据整页不入库。价格和库存失败保留原有数据，不写空覆盖。

## 验证边界

本次开发使用官方文档与模拟 API 验证身份隔离、重复同步、整页回滚、价格/库存、运费保留和沃尔玛提交/审核流程。SQLite 全套后端测试 527 项通过（5 项跳过），前端测试 73 项通过；另外在独立 PostgreSQL 16 测试库验证赛盈与相关筛选 22 项通过。页面已核对赛盈列表、商品档案、报价库存与预上架金额。未使用真实赛盈 AccessToken，未真实同步或刊登。上线配置后应先指定 1 个 SKU 同步，核对站点/仓库/物流/币种/价格/库存/运费，再建立预上架批次。当前每周自动巡查仍服务于既有大建云仓，不会自动将赛盈纳入巡查。
