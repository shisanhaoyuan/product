# 沃尔玛美国站正式上架

## 操作入口

同一商品上架其他店铺：在商品页面点击「预上架」，选择目标店铺后，在「复用已填写模板」选择以前店铺的刊登资料。每件商品独立选模板，也可不复用。模板需覆盖本次所有所选子 SKU；类目与标题尚未填写、SKU／ASIN 对应变化或已移入回收站的模板不会列出。创建后，类目、属性、图片和文案立即带入，标题、描述与卖点中的品牌切换为目标品牌；本次售价从来源基准重新计算，保留模板自定义 MSRP。

新批次的店铺 SKU、品牌编码和发货仓按目标店铺处理，不继承原店铺豁免或审核结果。跨品牌如编码池不足会明确提示补码；不复用旧编码凑数。资料需在目标店铺重新校验后才可提交。新批次修改不影响原模板，已提交的模板也可继续作为其他店铺的来源。复用不会自动运行 AI 覆盖模板，需要时可手动重新生成并校验。

从亚马逊商品库或大建云仓选择商品并创建预上架批次，打开批次详情，点击「填写上架资料」。本次填写属于独立批次，不覆盖商品库来源记录或数字酋长。

页面首先显示目标店铺、品牌、校验数量及发布数量。左侧按来源 SKU 和店铺 SKU 切换商品，右侧将「基本信息、图片与文案、必填属性」合并到 **商品刊登资料** 页面，用页内导航定位三个区域，不必切换标签。另保留选填属性和处理结果：

- **基本信息**：实际沃尔玛商品类型、店铺发货仓、GTIN/UPC/ISBN 或批准的豁免、标题、品牌、价格和履约。
- **图片与文案**：主图、附图、商品描述、卖点。图片可放大、本地添加、删除或设为主图。
- **必填属性**：按当前商品类型展示官方字段，红色星号标记必填；尺寸与单位并排填写。
- **选填属性**：默认仅显示已填内容，搜索或显示全部后添加。改变类目后，可检查并移除不受支持的旧属性。
- **处理结果**：逐 SKU 状态、中文原因、Feed ID 及历史提交；平台原始原因折叠查看。

编辑后自动保存，也可点「保存资料」。修改后的校验自动失效；离开页面时尝试保存，失败则阻止站内跳转。浏览器强制关闭、网络断开仍可能丢失未保存输入，请查看保存状态。

商品类型根据同一来源商品的类目名称、完整路径和已记录的 Product Type 自动匹配当前绑定店铺返回的真实选项。名称规范化后匹配，并支持明确的同义名称，例如云仓 `Sofas`、`Sectional Sofas` 对应 `Sofas & Couches`；不会将沙发套、沙发床等按关键词包含关系套入沙发类目。只有唯一候选才自动选择，已有有效选择通常保留；如果来源明确为室内、当前却为室外类型，则重新匹配并记录理由。提交锁定的商品保留原值。自动选择后加载该类型的官方属性；刷新来源后再次尝试补齐空类目。界面同时显示来源类目便于核对。

新建资料的空商品编码类型默认 **EAN**，编码值仍需真实来源或人工填写，不自动生成。来源已有 UPC、EAN、GTIN 等真实编码时保留对应类型、完整值及前导零；已保存的人工类型和豁免信息不被默认值覆盖。编码长度、校验位和平台豁免仍按正式校验规则执行。

## 店铺默认品牌与批次整理

在「店铺管理 → 沃尔玛绑定 → 生成前提配置」填写并保存「店铺默认品牌」。预上架选择该店铺时自动带入，可为当前批次临时修改；切换店铺会换成对应默认品牌，未设置的店铺清空品牌，避免沿用上一店铺。配置按系统店铺与实际 Partner ID 隔离，保存不修改已有批次。

预上架批次支持按状态、店铺筛选，以及搜索批次编号、店铺名或品牌。已取消记录可勾选、全选当前页后批量删除，移入回收站并从普通列表隐藏；回收站可批量恢复，恢复后仍为已取消，不会重新提交。已提交或仍在生成资料的批次不能删除。商品资料、已分配 SKU/EAN 与审计记录保留，删除不释放编码。

商品标题统一采用「目标店铺本批品牌＋商品标题」。先移除标题中已核验来源品牌和重复目标品牌，再把目标品牌放到开头；大小写忽略，尺寸、小数及普通商品词保留。未知单词不猜成品牌。准备资料、生成、保存和显式校验均应用，已有草稿可点「校验上架资料」更新，已提交锁定商品不改。首次升级需按新标题规则重新校验，之后不会仅因经过10分钟失效。此前失败任务需点「重新生成并校验」更新失败原因。

## 自动生成刊登资料

完整闭环的范围、状态、数据结构及验收标准见 [AI 自动刊登闭环设计](AI自动刊登闭环设计.md)。首版实施边界与未完成的真实环境验收已在文末注明。

AI 配置且店铺已绑定时，新建预上架批次会在后台自动生成；旧批次打开编辑器时也会为尚无任务的资料启动生成。可用「生成并校验／重新生成并校验」手动执行。生成期间临时锁定资料编辑及提交，关闭网页不影响后台执行；进度按 SKU 保存。任务异常超过 10 分钟会标为中断，重新生成不会让旧任务继续覆盖。普通生成任务服务重启后需检查中断状态并重试；平台资料失败触发的修复草稿单独保存编号，排队任务可恢复调度，运行中断则明确提示重新生成。

每个 SKU 的顺序为：补采本 SKU 来源 → 从绑定店铺真实类目选择类型 → 匹配仓库、真实编码或批准豁免 → 获取完整官方 Schema → 图片能力探测及同 SKU 识图 → 确定映射、Skill 默认及 AI 补缺 → 保存回读与指定店铺共享校验 → 最多3轮错误驱动修复 → 最终校验。来源、店铺授权或资料版本中途变化会停止写入。已有人工内容保留，价格、MSRP、库存、真实编码及 SKU 身份由程序保护，AI 无权更改。已提交或结果未知的 SKU 跳过。

迁移后的填写规则保存在 `catalog/listing_generation_rules.md`，服务独立运行，不调用原 ERP 上传脚本。AI 只接收当前 SKU 的必要事实和官方候选。能确定映射的字段无需模型；同一已完整任务、资料、绑定及缓存规格未变时重复点击复用结果。规格过期或变化后重新生成仍会复核官方字段。

普通物理属性的 AI 估算单独标记「AI 估算」及理由；不能估算产地、认证、Prop65、安全披露、保修、条码或豁免。普通属性按用户授权选择置信度最高的有效候选，低置信度也填写并标注推测；受保护字段缺少前提或接口失败仍保留中文原因，不编造完整状态。资料生成结束、资料校验通过、已发布是三个独立状态。逐字段依据可在「查看当前 SKU 的生成依据」展开。

2026-11-17 按用户明确授权补充 Skill 缺项默认值：来源及已有内容优先，缺失时由 Python 按实际 Schema 填入 No 类开关、Adult、China、Imported、小零件警告0、备货1及净内容1 Each（无 Each 时仅用真实 Case）等。记录为「用户规则」，不伪称来源或 AI 评分。未能从来源及 AI 获得的必填长度可兜底22英寸；重量没有此兜底。已有数量、单位、Yes、尺寸等不被默认覆盖。缺失描述从同 SKU 卖点和规格整理；真实条码及批准信息不能编造。类目调整后的不兼容旧字段移出提交资料，原值可在生成依据中展开查看。旧失败批次更新服务后点「重新生成并校验」即可应用，不自动刊登。

生成结果按真实字段合并提示：例如三次 AI 的床尺寸缺项与官方 bedSize 必填报错合并为一项，EAN 的空白、长度与格式错误也合并为一项，可展开查看原始原因。读取历史任务同样合并，不改历史审计及未通过状态。单次生成不重复请求同一缺项，只有新触发的条件字段会再分析。普通物理/款式属性允许基于本 SKU 的上下文合理估算并标注依据；床型、靠背结构等普通属性即使证据不全也按最可能候选填写，不套用22英寸或统一枚举。床尺寸识图任务携带实际 Schema 选项，优先图片标签和睡眠面尺寸，再按比例估算；直接采用最高置信度有效识图床型，缓存随任务版本、商品类型和候选变化失效。真实 EAN 或已批准的豁免需独立核验。

### AI 配置

类目和属性依据支持真实嵌套路径，例如 `content.copy.title`、`content.copy.features.0` 和 `content.attributes.Use Case`，逐层检查存在且内容非空；不将有效叶子引用误判为缺失。SKU 不符、候选无效、来源事实置信度不足、依据无效及室内户外冲突分别提示中文原因，类目失败始终定位到商品类型。修复后旧失败任务可点「重新生成并校验」重做，不自动提交。

当前接入 OpenAI 兼容接口 `https://www.aiwanwu.cc/v1`，模型 `gpt-6-astra`，使用流式 JSON 响应。密钥只在后端使用，不返回浏览器、不进入任务记录或 Git。本机配置为仓库旁的 `.env.listing-ai`（600 权限，已忽略）；服务器在 `/etc/jiwu.env` 配置以下变量，再重启 `jiwu` 服务。两处配置不会通过 Git 自动同步。

```ini
CATALOG_LISTING_AI_ENABLED=1
CATALOG_LISTING_AI_BASE_URL=https://www.aiwanwu.cc/v1
CATALOG_LISTING_AI_MODEL=gpt-6-astra
CATALOG_LISTING_AI_STREAM=1
CATALOG_LISTING_AI_KEY=实际密钥
```

勿把实际密钥填入示例文件或终端命令历史。需要临时停用自动生成时，将 `CATALOG_LISTING_AI_ENABLED=0` 并重启，已有商品资料保留。外部接口失败不自动切换平台，也不重试扣费请求；已完成的确定映射保留，失败原因在任务中显示。

## 三步执行

1. **校验上架资料**：先读取目标店铺的真实 taxonomy、启用的发货仓和当前版本商品规格，再按完整 JSON Schema 校验。缺少项可点击定位。GTIN/UPC 保留前导零并核对校验位；GTIN 豁免必须查询到同店铺、品牌、商品类型及类目的准确 APPROVED 申请编号，不能仅声明“已豁免”。
2. **提交沃尔玛**：仅管理员可执行。可只选择校验通过且允许提交的 SKU；确认框展示实际店铺、Partner ID、SKU 和售价，并要求输入店铺名。提交前再次检查授权、来源、黑名单和 SKU 对应关系。
3. **查看处理结果**：保存 Feed ID，并按 SKU 查询处理明细。收到 Feed ID 只表示接收；只有逐项处理成功、库存核验通过并且商品状态为 PUBLISHED，才显示「已发布」。查询结果可能写入所选店铺发货仓的该 SKU 库存。

若处理失败，可修改该 SKU 后重新校验，只重提失败项。成功、处理中、结果未知和库存待核验商品不会重新提交。库存待核验应修正来源库存或授权后继续查询。

## 审核进度与预上架流转

顶部「审核进度」集中展示已提交 SKU、店铺、来源 SKU、Feed ID、提交时间、结果更新时间和中文原因。按店铺、状态和关键字筛选；默认每个店铺＋实际账号＋平台 SKU 只展示最新提交，可勾选「包含历史重试」查看每次记录。统计按当前店铺与搜索条件计算，状态筛选作用于明细；草稿不计入提交数量。

提交后从预上架普通列表隐藏，在审核进度查看。最新结果为失败、提交被拒绝或未发布时，批次返回预上架并标记「审核失败」和失败 SKU 数；已成功及仍处理的 SKU 保持保护。只提交部分 SKU 的批次仍留在预上架处理未提交项。失败后重试成功提交，旧失败不会让批次重复返回；历史失败记录仍可查。结果未知留在审核进度，不当作失败重提。

页面每15秒读取本地持久化结果；原后台任务继续查询平台。管理员可点「查询进度」或「查询本页平台进度」，按原提交去重查询；只读模式不会提交 Feed、同步库存或生成修复任务，查询失败保留原结果。缺少 Feed ID 在原批次核对关联；店铺绑定变化时禁止查询旧账号。库存待核验需在原批次执行既有库存核验流程，不能把 Feed 接收或资料处理成功当作已发布。详情提供中文原因、折叠的原始原因和定位到对应 SKU 的批次入口。

本页面展示本系统的提交记录，不自动导入卖家中心或其他软件提交的商品。

## 价格、库存及身份保护

来源必须有有效核验时间；超过24小时不再阻止生成、资料校验或提交。亚马逊使用同 SKU／ASIN 来源采集原价乘本批倍率，四舍五入保留两位小数；缺原价自动采集一次，仍缺失则提示补采，不用 ERP 价格兜底；人工核对并保存有效售价后，可点击提醒旁「已验证」，解除当前 SKU 价格来源缺失限制。该确认随售价或来源变更失效，其余校验不豁免；大建云仓继续使用已有单价、打包费/运费规则。刷新来源不对已加倍率售价再次乘倍率，MSRP 初始可沿用两倍建议值，允许修改或按官方 Schema 省略，不再强制等于售价两倍；刷新来源保留已保存 MSRP。价格可在刊登资料中修改，仍按官方字段规范校验。

初次提交只允许来源库存已确认可用的商品。库存规则保持来源低于 10 写 0、大于或等于 10 写 10；库存写入前重新读取同一来源 SKU 的最新库存，过期或未知暂停写入。云仓供应商分仓与沃尔玛店铺发货仓分别处理，不能混用。

来源 SKU、店铺 SKU、商品 ID 与批次绑定关系不可更改。店铺 Partner ID 每次请求实时校验，绑定变更和资料变更会使校验失效；校验不设固定10分钟过期。库存结果按 SKU 对应，历史重试记录不能覆盖新提交的库存。

提交前先持久化发送记录和请求键。超时、断网、响应异常或提交后进程中断属于「结果未知」，不会自动重试 POST。需在卖家中心核对原 Feed ID，再在处理结果中关联；系统要求店铺、MP_ITEM 类型、`jiwu-提交编号.json` 文件名、完整 SKU 集合和数量均匹配。平台尚未返回完整明细时继续等待。无法确认的记录保持锁定，不以重新提交绕过。

## 部署

运行现有 Git 更新脚本安装 Python 锁定依赖并构建 Vue 前端；启动会自动执行 SQLite/PostgreSQL 迁移 20，保留来源商品、店铺凭证及既有批次。新增持久化内容包括刊登资料、规格缓存、提交、SKU 占用、事件、查询租约和资料生成任务，完整备份需包含数据库、图片目录与原加密主密钥。

沿用现有 `CATALOG_CREDENTIAL_KEY_FILE`，不要重建或覆盖主密钥。每个店铺在「店铺管理」绑定 Walmart US 授权，正式提交需要 `item` 和 `inventory` 均为 `full_access`。

`CATALOG_PUBLIC_ORIGIN` 必须为实际公网 HTTPS 站点。本地上传图片在提交时转换为签名访问地址，仅提交引用的图片可匿名读取；其余商品 API 仍需登录。图片地址应持续可用，不能改为 localhost、私网地址或需要登录的链接。外部图片 URL 的平台可达性、版权及质量仍以沃尔玛处理结果为准。

默认官方规格版本：`5.0.20260829-12_49_39-api`（2026-11-16 核对）。可用 `CATALOG_WALMART_SPEC_VERSION` 配置新版本；不能猜测或使用任意不匹配的 schema。规格按店铺/Partner/版本/类型缓存 24 小时，减少官方规格接口 3 次/分钟的限制；多类目首次加载可能限流，稍后重试即可，不自动退回旧字段。类目和仓库缓存 1 小时。

目前处理结果由页面按钮主动查询，不是后台自动轮询；不含订单处理、运单、退货和取消已发布商品。平台合规审核、品牌限制及图片处理仍可能导致本地校验通过后被平台拒绝。初次生产使用请先选少量真实商品，确认发布及库存结果后再扩大批量。

## 闭环操作与开关（2026-11-17）

1. 管理员在店铺管理配置该店实际发货仓、已批准豁免，或导入真实编码池；每条编码需保留真实归属依据。不同来源 SKU 不共享编码，同品同品牌跨店可复用。
2. 批次详情点“生成并校验”。逐 SKU 查看准备阶段、缺失前提、修复轮次、差异及证据。只有当前有效的共享校验通过才可提交；不设固定10分钟过期，配置或来源变化会失效。
3. 确认资料后由用户提交沃尔玛。后台恢复查询原 Feed，不重复提交。明确 DATA_ERROR 可以自动形成修复草稿，重新提交仍需确认。“查询并同步库存”是显式库存操作；后台轮询只读。

`CATALOG_LISTING_AI_VISION=0` 可停用识图，`CATALOG_LISTING_AI_SUPPLEMENT=0` 可停用来源补采；默认均为1。`CATALOG_LISTING_RESULT_WORKER=0` 停用后台结果查询，默认1。额外可信图片域名可在 `CATALOG_LISTING_IMAGE_HOSTS` 以逗号分隔配置；仍拒绝内网、异常重定向和无效图片。识图能力、来源验证码或第三方错误均单独显示，不能当成成功证据。

本轮闭环测试均使用隔离数据和模拟外部响应；未进行真实模型图片能力或真实上架验收。代码开发完成不代表线上商品已经通过沃尔玛审核。

闭环最终回归：SQLite 384项通过、5项跳过；隔离 PostgreSQL 386项通过、3项跳过；前端60项通过，格式、类型检查与生产构建通过，npm audit 无已知漏洞。新增测试覆盖三轮修复、无进展停止、人工改后恢复保护、编码并发唯一、图像能力探测与私网拒绝、原管理员失权、查询租约和修复排队恢复。页面以模拟店铺验收了生成结果、差异日志、前提配置、编码池与键盘焦点。

## EAN 表格导入与预上架随机分配（2026-11-17）

入口：店铺管理 → 沃尔玛绑定 → 管理真实商品编码池。选择或拖入 XLSX / CSV / TSV，先预览有效数、表内重复数和无效行，再确认导入。支持“UPC/EAN码”等表头及单列无标题编码；序号、ASIN、品牌等其他列不作为编码。限制8MB、10万行、50列；Excel 不执行公式或宏。编码按文本保存，数值单元格只有可确认完整整数或明确前导零掩码时才采用，科学计数法文本、无效校验位等记录为无效。

品牌可留空，表示尚未限定品牌，首次分配时固定绑定当前品牌；指定品牌的池优先使用。系统只校验格式与校验位，不声称已向 GS1 或平台核实归属。表格来源记为用户提供，文件摘要、名称、统计及操作者进入导入记录，不把上传表格解释成官方授权证明。

创建预上架批次的同一事务内，为每个子 SKU 随机抽取未使用编码并固定分配。来源商品原始编码、价格、库存、图片及文案不改；目标编码在预上架表格和刊登资料中显示。预览不占用编码，重复创建请求不再次抽取。来源、子 SKU、品牌相同的跨店上架或重试复用原编码；不同商品或不同品牌不会共用编码。已占用的历史刊登编码也不参与抽取；取消批次不回收编码。无可用编码时明确提示不足，禁止复用最后一个编码；补充池后可用“生成并校验”补齐。

重复导入（包含 EAN / UPC / GTIN 补零等价编码）保留已有绑定，跳过重复；指定了冲突品牌或 SKU 的导入整批回滚。支持全池搜索、已分配/未分配筛选、分页和导入记录。仅管理员可导入，沿用团队登录、CSRF 与同源校验。

新增迁移19（导入记录与可用池索引），新增 openpyxl / defusedxml 锁定依赖。正常 Git 部署更新会安装依赖并启动迁移；只更新代码不自动同步编码数据。各服务器需在自己的网页导入表格，不能覆盖线上数据库。

### EAN 导入入口与旧批次补码

店铺管理各页面的子导航提供「EAN 编码池 / 导入表格」；预上架刊登资料的「商品编码 / 豁免」输入框下方也提供直接导入和「从编码池补齐空白 EAN」。页面显示当前服务器池总数及该品牌可用数量；Git 只更新代码，不同步本机编码池。

旧批次打开编辑器、准备资料或点击补码时，在事务内独立补齐空白编码，不依赖 AI、类目选择、模型成功或沃尔玛店铺在线接口。导入后关闭窗口自动补码；也可手动点击补齐。只处理来源、SKU、品牌核对一致且允许编辑的行；保留非空编码及豁免，跳过处理中、结果未知和成功商品。生成运行中拒绝单独分配，乐观版本冲突或来源变化停止写入；重复点击沿用原绑定，不重复消耗。资料与批次概览同步更新，原来源价格、库存、文案和图片不改，旧校验失效后需重新校验。


### 店铺记录、图片与描述

商品卡片／列表和商品详情可查看本系统店铺上架记录，按逐 SKU 真实结果区分预上架、提交中、处理中、已发布与失败；ERP 来源记录不冒充 Walmart 发布记录。预上架商品缩略图可直接打开详情，刊登编辑器显示当前 SKU 资料，同时可打开完整商品档案。

刊登图片最多8张（含主图），添加超额文件时先提示减少选择；原始商品图库完整保留。生成时识别同 SKU 白底商品图、参数图，优先白底主图和参数附图；无可靠识图结果则按来源顺序取图并记录原因。描述依照原填写 Skill 作 Features / Product Information 分区、编号和逐条换行，清除禁用条款，与独立卖点去重，保留同 SKU 已核验规格；事实不足不编造补长度。已提交锁定行及历史提交快照不追改。


## 同一商品多变体上架

同一来源父商品在同一店铺中使用固定的变体组编号，子 SKU、商品编码、价格和库存仍各自独立。不同来源父商品不会因标题相似自动合并，不同店铺复用模板会重新生成组编号。

填写页「多变体上架」显示同组规格、差异属性和主变体。系统从当前店铺实际类目规格的 `variantAttributeNames` 可选范围中，使用子 SKU 自身的属性值自动选择能区分所有规格的组合；可人工调整差异属性、主变体和各规格值。不能确定的真实规格不会用 SKU 编号或虚构颜色代替，重复组合、缺失属性、类型或品牌不一致会给出中文提示并阻止提交。颜色变体在类目支持时使用自身色卡图或主图，支持本地图片转换为公开链接。

首次组建多变体组需在一个批次选择至少两个子 SKU；当前批次可编辑的同组子项必须一起校验、提交，勾选会整组联动。每个子项仍作为一个 MP_ITEM 条目传输，但共享 `variantGroupId` 与 `variantAttributeNames`，仅一个 `isPrimaryVariant=Yes`。收到失败结果后可更正失败子项并单独重试，组编号、分组属性和主变体沿用已提交记录；组内仍有处理中或结果未知的子项时先查询原批次。已成功子项不会跟随失败项重复提交。

更新后旧校验结果需重新校验。历史上已经作为独立商品提交的记录不会自动迁移或重新刊登，需先核对沃尔玛现有关系。官方规格通过及 Feed 接收不等于平台已完成变体关联，最终仍以沃尔玛处理和刊登结果为准。本功能测试使用官方规格样本与模拟接口，不执行真实刊登。

### Skill 变体属性匹配

移植 `digit-emperor-listing` 的管理多属性规则（2026-10-15 修订）：先占用所有同名字段，忽略大小写，Colour / Base Color 归入 Color；再将无法对应的来源属性，按字段名和本列实际值的本地语义匹配，映射到当前 API 类目允许、未占用且支持自定义文本的 Color、Size、Pattern、Finish、Theme、Shape、Snare Drum Size、Drum Shell Color、Frame Color。此步骤使用 Skill 的本地匹配规则，不调用 AI，不把本地排序标成 AI 置信度。

无空闲字段时，将同一子 SKU 的真实属性原值用 `**` 合并到已选的自定义字段，优先 Color。例如 `Black**24 Inch`；不改变大小写或单位，不跨 SKU 借值，不重复拼接。不将 Multipack Quantity 选为新分组的差异属性，但保留它作为独立数量字段的有效值。已提交分组沿用历史属性，避免自动改变平台关系。

保存、进入准备页及校验时，如果尚未提交的分组出现“总数均为 1”等重复组合，自动尝试上述规则。已有可用人工组合保留。页面可展开“属性对应依据”，数据库编辑事件保存原值、新值和匹配方法。字段有固定枚举、长度限制或来源差异缺失时，不强行填写或用 SKU 编造差异；保留具体问题供修正。此处的 Color 等字段可能按用户规则承接完整规格文字，映射依据中明确记录，并非宣称该文字本身就是实际颜色。
