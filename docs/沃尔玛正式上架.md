# 沃尔玛美国站正式上架

## 操作入口

从亚马逊商品库或大建云仓选择商品并创建预上架批次，打开批次详情，点击「填写上架资料」。本次填写属于独立批次，不覆盖商品库来源记录或数字酋长。

页面首先显示目标店铺、品牌、校验数量及发布数量。左侧按来源 SKU 和店铺 SKU 切换商品，右侧分为：

- **基本信息**：实际沃尔玛商品类型、店铺发货仓、GTIN/UPC/ISBN 或批准的豁免、标题、品牌、价格和履约。
- **图片与文案**：主图、附图、商品描述、卖点。图片可放大、本地添加、删除或设为主图。
- **必填属性**：按当前商品类型展示官方字段，红色星号标记必填；尺寸与单位并排填写。
- **选填属性**：默认仅显示已填内容，搜索或显示全部后添加。改变类目后，可检查并移除不受支持的旧属性。
- **处理结果**：逐 SKU 状态、中文原因、Feed ID 及历史提交；平台原始原因折叠查看。

编辑后自动保存，也可点「保存资料」。修改后的校验自动失效；离开页面时尝试保存，失败则阻止站内跳转。浏览器强制关闭、网络断开仍可能丢失未保存输入，请查看保存状态。

商品类型根据同一来源商品的类目名称、完整路径和已记录的 Product Type 自动匹配当前绑定店铺返回的真实选项。名称规范化后匹配，并支持明确的同义名称，例如云仓 `Sofas`、`Sectional Sofas` 对应 `Sofas & Couches`；不会将沙发套、沙发床等按关键词包含关系套入沙发类目。只有唯一候选才自动选择，已手动选择或提交锁定的商品保留原值。自动选择后加载该类型的官方属性；刷新来源后再次尝试补齐空类目。界面同时显示来源类目便于核对。

新建资料的空商品编码类型默认 **EAN**，编码值仍需真实来源或人工填写，不自动生成。来源已有 UPC、EAN、GTIN 等真实编码时保留对应类型、完整值及前导零；已保存的人工类型和豁免信息不被默认值覆盖。编码长度、校验位和平台豁免仍按正式校验规则执行。

## 三步执行

1. **校验上架资料**：先读取目标店铺的真实 taxonomy、启用的发货仓和当前版本商品规格，再按完整 JSON Schema 校验。缺少项可点击定位。GTIN/UPC 保留前导零并核对校验位；GTIN 豁免必须查询到同店铺、品牌、商品类型及类目的准确 APPROVED 申请编号，不能仅声明“已豁免”。
2. **提交沃尔玛**：仅管理员可执行。可只选择校验通过且允许提交的 SKU；确认框展示实际店铺、Partner ID、SKU 和售价，并要求输入店铺名。提交前再次检查授权、来源、黑名单和 SKU 对应关系。
3. **查看处理结果**：保存 Feed ID，并按 SKU 查询处理明细。收到 Feed ID 只表示接收；只有逐项处理成功、库存核验通过并且商品状态为 PUBLISHED，才显示「已发布」。查询结果可能写入所选店铺发货仓的该 SKU 库存。

若处理失败，可修改该 SKU 后重新校验，只重提失败项。成功、处理中、结果未知和库存待核验商品不会重新提交。库存待核验应修正来源库存或授权后继续查询。

## 价格、库存及身份保护

来源必须有真实核验时间，价格和库存依据不超过 24 小时。亚马逊继续使用同 SKU 已核验的来源含运费价格与首次 ERP 原价较高值乘本批倍率，多变体沿用 .99 尾价；大建云仓继续使用已有单价、打包费/运费规则。刷新来源不对已加倍率售价再次乘倍率，并更新 MSRP 为该商品组最高最终售价的 2 倍。价格可在刊登资料中修改，但仍需重新校验 MSRP。

初次提交只允许来源库存已确认可用的商品。库存规则保持来源低于 10 写 0、大于或等于 10 写 10；库存写入前重新读取同一来源 SKU 的最新库存，过期或未知暂停写入。云仓供应商分仓与沃尔玛店铺发货仓分别处理，不能混用。

来源 SKU、店铺 SKU、商品 ID 与批次绑定关系不可更改。店铺 Partner ID 每次请求实时校验，绑定变更和资料变更会使校验失效；校验有效期为 10 分钟。库存结果按 SKU 对应，历史重试记录不能覆盖新提交的库存。

提交前先持久化发送记录和请求键。超时、断网、响应异常或提交后进程中断属于「结果未知」，不会自动重试 POST。需在卖家中心核对原 Feed ID，再在处理结果中关联；系统要求店铺、MP_ITEM 类型、`jiwu-提交编号.json` 文件名、完整 SKU 集合和数量均匹配。平台尚未返回完整明细时继续等待。无法确认的记录保持锁定，不以重新提交绕过。

## 部署

运行现有 Git 更新脚本安装 Python 锁定依赖并构建 Vue 前端；启动会自动执行 SQLite/PostgreSQL 迁移 16，保留来源商品、店铺凭证及既有批次。新增持久化内容包括刊登资料、规格缓存、提交、SKU 占用、事件和查询租约，完整备份需包含数据库、图片目录与原加密主密钥。

沿用现有 `CATALOG_CREDENTIAL_KEY_FILE`，不要重建或覆盖主密钥。每个店铺在「店铺管理」绑定 Walmart US 授权，正式提交需要 `item` 和 `inventory` 均为 `full_access`。

`CATALOG_PUBLIC_ORIGIN` 必须为实际公网 HTTPS 站点。本地上传图片在提交时转换为签名访问地址，仅提交引用的图片可匿名读取；其余商品 API 仍需登录。图片地址应持续可用，不能改为 localhost、私网地址或需要登录的链接。外部图片 URL 的平台可达性、版权及质量仍以沃尔玛处理结果为准。

默认官方规格版本：`5.0.20260829-12_49_39-api`（2026-11-16 核对）。可用 `CATALOG_WALMART_SPEC_VERSION` 配置新版本；不能猜测或使用任意不匹配的 schema。规格按店铺/Partner/版本/类型缓存 24 小时，减少官方规格接口 3 次/分钟的限制；多类目首次加载可能限流，稍后重试即可，不自动退回旧字段。类目和仓库缓存 1 小时。

目前处理结果由页面按钮主动查询，不是后台自动轮询；不含订单处理、运单、退货和取消已发布商品。平台合规审核、品牌限制及图片处理仍可能导致本地校验通过后被平台拒绝。初次生产使用请先选少量真实商品，确认发布及库存结果后再扩大批量。
