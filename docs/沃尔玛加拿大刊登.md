# 加拿大云仓 → Walmart Canada

加拿大云仓商品可在「商品库 → 大建云仓 Canada」选择商品，点击「预上架」，选择绑定为 CA 的店铺。预上架价格、倍率计算及最终售价均按 CAD，不进行 USD/CAD 换汇。美国来源与加拿大来源不能跨站提交。共享填写引擎沿用默认规则、同 SKU 来源、AI 补全、完整校验及失败修复。

## 首次使用：加拿大官方类目规格

加拿大 OAuth 使用 Walmart Global API，正式刊登 feedType 为 `MP_ITEM_INTL`。截至 2026-11-24，Global 文档中的 Get spec、Taxonomy 接口明确仅限 US；不能将加拿大请求改一个请求头后继续调用美国规格接口。

系统内置并自动加载[加拿大官方完整规格](https://developer.walmart.com/file/mp/ca/CA_MP_ITEM_INTL_SPEC.json)，无需首次手动导入，也无需服务器联网下载。2026-11-24 核验的文件内部版本为 **3.16**，含 **80 个商品类型**；以文件内部版本为准，不把文档表中的 MP 4.X 或卖家中心 Spec 5.0 混用到本流程。此为随代码部署的固定快照，不会静默升级最新规格。原始文件以 gzip 保存，加载时校验 SHA-256；仅清理官方文件中类型不符合 Draft 7 的 `examples` 文档注释，保留所有校验约束。

官方合并规格未提供商品类型到 `subCategory` 的对应关系，且该 Header 字段不是必填，默认省略，不猜测映射。Header 采用 `WALMART_CA`、`marketplace`、`REPLACE`、`EXTERNAL`、`3.16` 及允许的语言列表。只有当导入的正式类目规格明确提供子类目时才使用该值。

管理员仍可在「填写上架资料」顶部点击「替换加拿大官方规格」导入兼容的完整 JSON Schema（Draft 4 或 Draft 7），店铺已导入规格优先于内置快照。**`bulk-item-setup.zip` 是商品请求示例；`CA_MP_ITEM_MATCH.json` 是匹配商品的另一种定义，两者均不能代替本流程的新建商品完整 JSON Schema。** Excel 模板也不能直接作为 JSON Schema 导入。

若官方 schema 为 Header 的版本、子类目、语言等提供唯一 enum/const/default，可直接导入原文件；否则使用下面的包裹格式，`header` 填写该加拿大官方规格对应的真实 Header，`schema` 替换为完整原始 JSON Schema 对象。不能把美国规格改成 `WALMART_CA` 后使用。

```json
{
  "specifications": [
    {
      "header": {
        "mart": "WALMART_CA",
        "sellingChannel": "marketplace",
        "processMode": "REPLACE",
        "subset": "EXTERNAL",
        "locale": ["en", "fr"],
        "version": "填写官方版本",
        "subCategory": "填写官方加拿大子类目"
      },
      "schema": {}
    }
  ]
}
```

上面是文件结构说明，含占位内容，不能直接导入。一次可导入同版本多个类目；同版本再次导入会合并更新，切换版本会替换店铺当前规格。规格按店铺 OAuth 身份隔离并持久保存，不会因缓存时间到期失效。同店铺正在生成时禁止更新规格；已有提交记录的批次禁止切换规格。更换规格会使旧校验失效，需重新校验。

## 填充、提交与结果

进入页面即可按实际加拿大类目自动选择并进行 AI 填充。编辑器继续显示普通文本，提交时按加拿大官方格式转换英文多语言字段，例如 `productName: {"en": "..."}`。最终校验保留原始官方 schema 的条件、枚举、必填与数量限制。当前支持允许英文刊登的规格；要求法语等其他语言必填的规格会明确拒绝导入。

重量按加拿大要求填写为 `{"measure": 12.345, "unit": "lb"}`，来源有明确单位时转换为磅并遵守 0.001 精度。旧模板中的磅重数值会转换为对象。原产国沿用用户指定 China 默认规则，在加拿大转换为 `CN - China`，审计标明用户规则，不伪称供应商事实。

加拿大必填 `productTaxCode` 使用用户提供的 `Taxability_Matrix_Canada_May2026.xls` 中 `GS List` 的 8,227 个商品／服务编码。完整编码、英文说明、四级分类及原表行号存放在 `catalog/specifications/canada-tax-codes-2026-05.json.gz`，清单记录原文件与字典的 SHA-256；运行时仅载入一次，无需安装 Excel 解析库或迁移数据库。省份税率矩阵和 `EU List` 的实体／用途代码不作为商品税码导入，不据此自动计算税率。

生成仅补空白税码：同 SKU 明确来源编码优先，否则 AI 先从完整分类列表选组，再从该组完整编码中匹配一项；禁止返回字典外编码、其他 SKU 的依据或已保留／停用编码。不固定把所有商品填成一般应税商品，也不猜测税率优惠资格。审计记录匹配原因、来源引用、置信度、表格版本、行号与字典摘要。已有税码保留，员工可在填写页按编码或英文说明搜索、更换；美国店铺不使用此表。正式校验及提交共用字典有效性检查，字典摘要加入校验资源指纹。

更新服务器后，旧批次点击「重新采集并生成」即可补齐空白税码，随后重新校验。AI 不可用或返回不合规编码时显示具体原因，员工仍可从税码库选择。离线测试仅验证系统映射、校验和 Feed 字段，不能替代真实沃尔玛受理结果。

按「校验上架资料 → 提交沃尔玛 → 查看处理结果」操作。提交使用 `WM_MARKET: ca`、`WM_GLOBAL_VERSION: 3.1`，记录 Feed ID；同一次选择必须使用相同的官方 Header，只有 Header 相同的 SKU 可以一起提交。提交结果未知时禁止重发，可通过原 Feed ID、原文件名、完整 SKU 清单核对后恢复。逐项失败会显示平台原文与中文分类，修正后仅重试失败 SKU。只有商品查询实际返回 `PUBLISHED` 才标为发布成功。

加拿大当前使用店铺默认库存：页面选择器是系统的“加拿大站默认库存”，请求中省略可选 `shipNode`，不伪造平台仓库编号。暂不开放加拿大多发货仓选择、自动 GTIN 豁免核验、店铺商品管理或每周巡查向店铺自动改价/改库存；加拿大每周巡查继续更新商品库。需使用真实 EAN/UPC/GTIN 编码。

美国站保持原有在线获取官方规格及刊登流程。本次使用模拟接口验证，未向真实加拿大店铺提交商品；实际授权、类目权限、品牌/编码及最终审核以 Walmart 返回为准。
