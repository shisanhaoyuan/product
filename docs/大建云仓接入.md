# 大建云仓 Buyer API 接入

本实现依据 2026-11-13 读取的 [Open API 2.0 官方文档](https://www.gigab2b.com/index.php?route=information/open_api/index&doc_id=3&api_lang=zh-cn)，接入商品库「数据接入 → 大建云仓」。没有调用订单创建、库存修改或刊登接口。

## 配置

在服务器 `/etc/jiwu.env` 中添加以下配置，保留已有数据库、图片存储及登录配置：

```dotenv
CATALOG_GIGA_ENVIRONMENT=sandbox
CATALOG_GIGA_CLIENT_ID=替换为测试环境ClientID
CATALOG_GIGA_CLIENT_SECRET=替换为测试环境ClientSecret
```

生产环境将 environment 改成 `production`，并使用对应生产凭证。截图中已经展示过的密钥先在大建云仓重置。不要把密钥写进代码、Git、浏览器或聊天。

编辑文件后维持原先的 `jiwu:jiwu`、`600` 权限，执行 `systemctl restart jiwu`。应用读取文件的原有安全配置机制不变。页面显示“测试环境／生产环境”只表示配置存在，不代表已通过远程认证；实际同步成功才证明调用通过。

地域和币种由 Buyer 账号及响应决定，官方四个接口没有独立地域请求参数。本系统不强制 USD，不进行汇率换算。测试和生产、不同 Client ID 数据相互隔离；换 Client ID 会产生新来源账号，需要人工决定旧账号数据如何处理。

## 商品库分区

- 顶部「亚马逊商品库」`/#/products`：只显示 Amazon 来源，保留原有预上架与待复核流程。
- 顶部「大建云仓」`/#/giga-products`：只显示 GigaB2B 来源，按供应商 SKU 查看。详情地址为 `/#/giga-product/<id>`。
- 两个入口的商品数、类目、品牌、店铺、日期选项、搜索、分页和 CSV 导出都按来源独立过滤。切换来源清空选择，不带入上一库的预上架选择。
- 同一系统按来源逻辑分区，不移动或删除旧商品，也不复制两个数据库。没有传 source 的旧接口仍可获取全库数据，保持既有接入兼容；网页固定传入对应来源。

## 使用

1. 在大建云仓把需要的商品加入 Buyer 收藏夹（或使用已有囤货商品）。API 不支持全站商品拉取。
2. 商品库使用管理员或编辑员登录，打开「数据接入」，点击「同步商品库」。只读成员不能触发。
3. 每页 100 件，依次查询列表、详情、价格、库存。保持页面打开，完成后查看新增、更新、未变化数量。支持停止后续页；已完成页保留。
4. 若某页失败，该页不入库；已完成页不回滚。可重新从第一页同步，按账号＋环境＋SKU 更新，不重复建档。同步时建议不要同时修改大建云仓收藏夹，分页接口不提供一致性快照。
5. 在商品库搜索供应商 SKU、卖家或 GigaB2B。商品详情「大建云仓 · 最新来源资料」显示分项事实及可展开 JSON。

## 字段与价格库存

- SKU 使用 API `sku`，ASIN 留空。商品来源标为 GigaB2B，存放在“大建云仓来源库”，不伪造目标店铺或 ERP 模板。模板内部标识为 `GIGA:<sku>`。
- 主图和附图链接去重保存并正常展示。**当前保留官方图片 URL，不下载为服务器图片副本**；签名链接失效时需要再次同步。已有本地上传图片功能不变。
- 价格取原价 `price`，不套用上架倍率；专享价、折扣价、币种、普通／偏远运费、运费区间及阶梯价完整保留在来源资料。没有运费时显示“未返回”，不按 0 处理。普通地区运费不是所有收货地址的实际运费承诺。
- 库存使用 `sellerInventoryInfo.sellerAvailableInventory`（平台可采购数量）。不加上 Buyer 自有、共享、在途、锁定或促销库存，也不把仓库范围最大值相加。未知库存留空，真实 0 保留为 0。不应用 ERP 的 0/10 上架规则。
- 卖家、标题、特点、描述、UPC、品牌、来源类目一并导入；GIGA 类目供本库筛选，不冒充 Walmart Product Type。
- 组合配件与关联产品保留在原始 JSON，不自动组成子变体。不虚构未提供的商品详情 URL。
- 详情／价格／库存严格按 SKU 对应，重复、错配、少返回或非法金额／库存整页拒绝；不会用另一个 SKU 补齐。
- 每次同步保留来源快照，内容未变不重复生成商品快照。已有手工编辑层保留；最新接口值始终可在来源资料中查看。
- 来源资料不等于“ERP 双保存／已核验完整”。现有 Amazon 价格审计与预上架流程不自动套用到 GIGA 商品；本次仅同步到商品库，后续上架适配另行实现。

## 协议与运行约束

- 域名：生产 `https://openapi.gigab2b.com`；测试 `https://openapi-sandbox.gigab2b.com`。固定白名单，不接受浏览器指定任意域名；禁止携带签名跟随重定向。
- 签名：消息 `ClientID&路径&毫秒时间戳&nonce`；HMAC 密钥 `ClientID&ClientSecret&nonce`；HMAC-SHA256 十六进制字符串再 Base64。nonce 为 10 位数字。
- 文档 5：`POST /b2b-overseas-api/v1/buyer/product/skus/v1`（每页 100，按首次发布时间升序）。
- 文档 6：`POST /b2b-overseas-api/v1/buyer/product/detailInfo/v1`。
- 文档 7：`POST /b2b-overseas-api/v1/buyer/product/price/v1`。
- 文档 19：`POST /b2b-overseas-api/v1/buyer/inventory/quantity/v2`。
- 全部顺序限速为间隔至少 1.1 秒；网络错误、429、5xx 最多重试一次。查询总时限 90 秒，HTTP 超时 10 秒；Nginx `proxy_read_timeout` 建议维持现有 120 秒。
- 数据库租约避免同一账号多 Web worker 同时同步；意外进程退出最多等待 180 秒重新尝试。错误响应不转发第三方原始正文，避免泄露签名或密钥。
- 数据库 schema 13 为没有 ASIN 的供应商 SKU 提供独立身份；保留原有 Amazon ID 和真实 ASIN 唯一约束。部署前按原部署流程备份数据库。正常升级只迁移结构，不导入或覆盖本地开发数据。

## 验证边界

本地使用模拟官方协议响应测试签名、SKU 错位、幂等更新、权限、分页、失败回滚及手工编辑保留；没有使用截图中的凭证发起真实查询。配置有效密钥后，先同步少量已收藏商品，逐项核对 SKU、币种、原价、运费、库存及图片。
